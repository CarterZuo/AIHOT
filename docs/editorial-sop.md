# 汽车产业情报｜编辑运营 SOP

版本：1.2 · 2026-10-24 · 适用：本机、内部评估阶段；已同步ED-20261024-008四层AI收录及ED-20261024-010企业应用地域口径。

目标：让编辑能够判断“源是否值得收、材料是否读对、内容是否判对、页面是否呈现正确”，通过项目已有入口形成可追溯的纠错与复验闭环。

本文是操作规程，不代表已经执行全部检查或部署新自动化。常规巡检不自行修改业务代码、行业提示词、分类和门槛文件；用户已明确批准的专项配置调整按decision-log.md记录的范围执行。不新增付费服务、备份或外部推送。既有原生定时采集继续运行，使用当前已授权的Magpie网关及安全校验：默认antigravity/gemini-3.8-flash，understand、summarize、factReview使用magpie/codex/gpt-6.1-sol；每次维护仍以后台与实际回执核对，不恢复历史OpenCodex配置。新稿事实审核与最终标题、摘要、关注价值哈希绑定；修改文案后须验证审核及公开资格，不能用人工覆盖绕过。冻结日报已有原生摘要纠错接口，仅能采用当前审核通过的原生摘要，须核版本、归档及审计。无 VPN 直连检测按用户决定延期。

## 1. 一张流程图对应六道检查

**信源准入 → 材料核验 → 发布判断 → 栏目审校 → 热点与日报复核 → 错例归档与配置复验**

发生问题，先找出错环节；仅处理必要环节。配置保存、任务入队、回执完成，都不能单独作为内容正确的证明。

| 检查环节 | 编辑要回答的问题 | 留下的证据 | 通过条件 |
|---|---|---|---|
| 信源 | 能补充哪个业务范围？原始发布者是谁？ | 信源ID、原站栏目、试抓样例、发布者分组 | 有真实文章、可追溯来源，访问方式符合当前范围 |
| 材料 | 文章、时间、正文和来源读对了吗？ | 原文链接、材料ID、原文与后台对照 | 不把导航当文章，不补造日期，不把菜单当正文 |
| 发布 | 为什么公开、为什么未公开、为什么精选？ | 预筛、摘要、评分、归组、公开状态 | 原因与实际证据一致，低分不等于不能进全部动态 |
| 栏目 | 分类和文字是否符合业务口径？ | 栏目、原文关键段、修改前后内容 | 主体、数字、日期、适用条件和事实阶段正确 |
| 聚合 | 热点和日报有没有误合并、虚增来源或漏刊？ | 事件ID、独立发布者、刊期、运行记录 | 真正多源；日报窗口与发布结果一致 |
| 复验 | 问题是否解决，是否引入新问题？ | 修改理由、审计记录、后续原生运行和页面 | 对照原文复验通过；未解决项保留 |

## 2. 分工与节奏

以下为建议执行安排，不是系统已有定时配置，也不是已承诺的服务时限。一个人可兼任多个角色，但记录中应区分业务判断和技术操作。

- **编辑**：抽查来源、核对原文、判断栏目和价值、纠正单篇内容、维护错例。
- **运维**：维护后台信源配置，核对日期/正文解析，定位队列、网络和模型错误，执行限定范围的原生重处理。
- **业务负责人**：确认收录边界、重点范围与人工标注；决定是否接受覆盖缺口、是否调整评分标准。

| 频次/触发 | 建议任务 | 建议样本范围 |
|---|---|---|
| 每日首次查看，日报截稿后 | 先看运行，再看信源，再抽查公开和未公开内容 | 当期日报全量；当日新增精选全量；其余分层抽查 |
| 日常内容抽检 | 同时看“该进没进”和“进了不该进” | 全部动态每个有新增的栏目抽3条；未公开按缺日期、BLOCK、UNKNOWN、待处理每类抽3条。不足则全量；重叠样本只计一次 |
| 新增源或修改源配置后 | 试抓→核对原文→保存→观察原生采集→页面回读 | 建议5条，含最新、旧文、边界条目；不足5条全部检查并注明样本不足 |
| 每周 | 信源质量与覆盖复盘；同类错例归因 | 遍历全部信源状态；轮换抽查未覆盖源，重要异常优先 |
| 出现重大事实错误 | 立即核实影响范围，按既有权限纠正或下架 | 该文章、所属事件、已出现的栏目与刊物，不只改首页卡片 |

抽样数量是起步建议，可根据实际工作量调整；不能把抽样合格说成全站准确率100%。不以公开率越高越好作为目标。

## 3. 信源是否合适：准入与保留

入口：[信源后台](http://localhost:3000/admin/sources)。新增或修改前先记录原配置，保留可恢复的配置值；这不等于启用数据库备份。

1. **明确覆盖贡献**：给源标出国家/地区、车企或车型、内容形态、预期栏目。全国31省区市逐一登记，不能用“有政府源”代替完整覆盖；出口按中东、俄罗斯、东南亚、中亚列缺口，代表国家不等于整个区域。
2. **确认发布者与证据属性**：官方公告、独立媒体、客户自述分别记录。核对T1/T1_5/T2分级，不因名称含“官方”或媒体知名就升级；同一发布者的多个栏目不作为独立多源。
3. **确认访问与许可**：仅使用当前授权的公开免费访问方式，保持安全校验。按2026-10-25用户最新决定，本机站启用源开放已有可靠正文，新源默认开启站内全文；RSS全文仍关闭，未知外部源仍隔离。展示配置不代表已核实来源转载许可，不绕过付费墙或访问权限，权利限制与正文质量问题分别记录。当前VPN环境成功不能记作无VPN直连成功。
4. **在后台试抓并逐条打开原文**：核对列表条目是否真文章；日期是否属于该文章；摘要是否正文；链接是否进入正确原文。预览有条目只证明取得列表，不等于全文、分析或公开通过。预览会访问原站；不要切换到需要付费的适配方式。
5. **决定处理**：合适且解析正确→启用；业务合适但解析有问题→修配置后复验；无相关产出或主要为噪声→保留证据后暂停/缩小栏目；因网络暂不可用→登记原因、观察原生退避，不推定内容无价值。
6. **观察实际周期**：等待原生采集，核对新增材料与后续状态。保存配置不等于生效验收；试抓不等于已入库。至少查看一次后续实际采集；“长期稳定”必须有跨周期记录。

本品：CX-5、CX-50、CX-30、MAZDA 3 昂克赛拉、EZ-6、EZ-60。竞品：EZ-60对应日产NX8、深蓝S07、海狮06、零跑C11；CX-5对应锋兰达、逍客；EZ-6对应**日产N7**、比亚迪汉；MAZDA 3 昂克赛拉对应思域、卡罗拉；CX-50对应CR-V、RAV4。CX-30尚无指定竞品，不能自行补成已确认范围。

## 4. 入库是否准确：先检查材料，不先责怪模型

入口：[内容诊断](http://localhost:3000/admin/content)，按标题搜索，进入单篇链路。对照原文检查以下项目。

| 检查项 | 合格口径 | 常见误判 |
|---|---|---|
| 文章身份 | 标题、链接和正文属于同一篇；保留来源 | 首页、联系我们、推荐模块混入新闻 |
| 发布日期 | 来源可证实；记录时区与日期精度 | 用采集日冒充发布日期；把页面更新时间当发布日；补造时分秒 |
| 正文/摘要 | 是该文章的有效文字；缺失明确标注 | `unconfirmed`被当成全文成功；把菜单和视频播放器文字当正文 |
| 数字和对象 | 车型、年份、价格口径、单位和条件一致 | 指导价写成成交价；不同年款或日产N7/腾势N7混淆 |
| 重复材料 | 同网址/内容与跨源报道正确区分 | 用多个栏目虚增文章或独立发布者 |
| 处理状态 | 状态、最近错误和回执对应同一修订 | 队列completed就宣称已取正文；历史错误当作本轮故障 |

日期配置可使用列表的 `publishedAtSelector` / `publishedAtRegex`，JSON的 `publishedAtPath`，以及 `detail.publishedAtSelector`、`detail.publishedAtUtcOffset` 等。选择器必须按原站实际结构填写，不能复制其他网站的值直接投入运行。详情页真实日期优先规则只在有原文证据时启用。列表没有日期时，原生详情补全可以后续继续尝试；并非所有错误配置都会自动自愈。

目前不批量手工改历史日期或回灌标记。发现历史时间错误，记录原文证据和受影响材料，先修读取配置；若仍需要逐篇日期更正，交运维核验现有原生更正能力与当前授权范围，不直接写数据库。

## 5. 未公开与未精选：用原因树定位

先确认用户看的入口：**首页精选、全部动态、栏目、主题、热点、日报**不是同一个集合。同时核对筛选条件、分页、日期窗口和可见时间。不能把首页数量当成所有已公开数量。

| 观察到的状态 | 下一步检查 | 合理处理 |
|---|---|---|
| 新建/失败/重试 | 原生消费者、最近错误、重试时间、对应修订 | 判断网络/材料/配置/模型格式问题；到期后观察真实执行，不反复点击 |
| BLOCK | 预筛理由与原文是否确实无关 | 正确拦截→保留；错拦→入错例，核对材料完整性，必要时限定重评 |
| UNKNOWN或无摘要 | 是否只有标题、正文未取得，或误采页面 | 先补材料/收紧列表，不能凭标题替模型写事实 |
| 相关性PASS、摘要已有但未入公开池 | 历史回灌是否缺可信日期；来源参与方式、公开资格 | 按真实来源补日期，核对资格；不通过改回灌标记绕过 |
| 已公开但未精选 | 两次分数、信源等级、归组与新增价值 | 低分通常仍可在全部动态；足分也须完成归组，不因数量少强制精选 |
| 后台有记录、前台找不到 | 是否下架、仅摘要、尚未到可见时间；栏目/标签/分页 | 先核对发布层与页面；搜索收录开关不等于公开资格 |

当前精选门槛：T1平均60、T1_5平均65、T2平均76；同一标准独立评分两次。评价实质份量、信息增量、证据强度、读者关联与可用性，按内容类型加权。分数不是真实性概率。门槛沿用框架值，尚不能声称完成本站人工样本校准。

## 6. 八个栏目如何审校

各栏目都要有可追溯来源、准确标题摘要和原文链接；摘要完整指保留影响理解的核心条件，不要求转载全文。分类以当前 `industry/taxonomy.ts` 的guide为准。

| 栏目 | 必须保留的内容 | 不能混淆的边界 |
|---|---|---|
| 国家政策 | 发布机关、政策阶段、对象、条件、生效/截止日期 | 征求意见≠已实施；地方执行归地方政策，出口政策归出口 |
| 地方政策 | 省市、适用人群/车辆、金额与条件、办理时间 | 地方补贴≠全国政策；公示、申报与实际兑现不同 |
| 企业动态 | 企业主体、具体动作、经营数据期间与单位 | 品牌国别≠所有制；合作签约≠已落地收益 |
| 产品动态 | 车型年款、上市/预售阶段、价格类型、权益与限制 | 官方发布归产品；媒体实测不写成官方承诺 |
| 客户服务 | 适用车辆/客户、服务范围、质保与召回条件 | 正式召回归服务；长马个案投诉归长马口碑 |
| 汽车出口 | 中国或目的国、政策效力、认证/关税条件、业务环节 | 目标市场与实际出口不同；提案、解释与生效规则不同 |
| 长马口碑 | 车型、媒体/车主/投诉方归属、测试条件、企业回应 | 个案不推算缺陷率；负面不自动高分；不同车型问题不拼接 |
| 数字化与AI | 已批准四层：汽车数智应用、企业转型应用、AI产业动态、AI社区观察；核对主体、方法、阶段、基准及限制 | 无汽车关联不再是拒收理由；社区内容须有实质证据并保留身份；四层不等于强制排序或自动精选 |

主题页另查主体与标签：主题按公司或标签聚合，不能仅因标题出现车型词就认定分类正确；“长马口碑”主题的相关内容仍需核对长马主体。单篇分类纠正不能代替系统性分类标准的优化。

## 7. 纠错操作：选择最小必要动作

以下是未来操作时的原生入口说明，本次制作SOP未执行这些修改。编辑应在现有权限和授权范围内操作。

| 问题 | 原生入口/动作 | 验证与回退 |
|---|---|---|
| 导航误采、日期/摘要没读对 | 信源→编辑采集JSON→预览→保存 | 留修改前JSON；核对同一组原文样本和新采集条目；变差则恢复旧配置 |
| 单篇标题、摘要、栏目或标签错误 | 内容诊断→人工修正，填写事实依据与理由 | 保存后回读前台和诊断；人工值优先，后续重评不会自动覆盖；恢复时清除对应人工覆盖 |
| 正文缺失 | 内容诊断→重新抽取正文，或等待原生重试 | 先确认失败原因已改变；若仍要求未启用的付费提取，不反复触发，保留未确认状态 |
| 材料已修好但判断仍旧 | 内容诊断→对当前修订重新评估 | 会使用现有模型并记录回执；限定材料清单，查看新判断和公开结果，不清除历史失败记录 |
| 评分达标却未精选/事件关系有误 | 查看归组证据，必要时重新归组或已有人工事件纠正入口 | 人工归组关系不会被自动覆盖；仅同车型不等于同一事件；回读事件及精选 |
| 内容造成明确误导 | 内容诊断→人工修正；无法立即修正时按既有权限下架 | 核对网页与事件/刊物影响；下架记录保留，纠正后再核实恢复条件 |
| 页面正文图片/链接展示有问题 | “更新正文展示”先预览 | 只适用于展示问题，不作为补正文或重评替代；检查预览差异再应用 |

人工评分、强制入选与公开资格是不同字段；不要以手工提高分数解决缺日期、缺正文或误分类。后台“推送”选项不能作为开启外部服务的授权，本机全局推送保持关闭。

## 8. 热点与日报的编辑复核

**热点**：先核对热度任务是否执行，再看候选事件是否达到独立参与方门槛。车质网多个车型入口仍是一家发布者；同一个车型的上市、投诉、评测不能自动当作同一次新闻。热点0可能是样本不足，也可能是召回/归组问题，必须结合证据判断，不能直接降低门槛。

**日报**：默认北京时间08:00截稿，覆盖前一天08:00至当天08:00，原生每半小时检查到期刊物；截稿后等待任务真实完成再验收。检查刊期、头条、正文与快讯、来源、重复事件及关键事实。日报按规则编排，不另调用模型生成条目；周/月报由日报汇编，并对导语使用模型。

静默刊表示窗口内有材料经过判断但没有新事件；完全没有资料经过判断仍可能失败。刊物存在、静默刊生成、有内容日报生成、内容正确是四个不同结论。已出刊不因定时检查自动重写；分类更正等原生支持的传播效果需逐处回读，不承诺整期正文自动修复。

运行页的旧失败与当前失败分开记录；模型请求completed不等于编辑判断正确，采集ok不等于详情全部完整，禁用推送的任务ok不等于已投递。

## 9. 每周如何优化：先错例，再标准，最后门槛

### 当前无代码变更范围内

1. 将问题归为：采集范围、日期、正文、行业相关性、分类、摘要事实、精选价值、归组、发布/刊物。记录原文、现状、期望及依据。
2. 同类问题归并到信源或步骤；先修采集配置。单篇纠正只解决该篇，不称作模型学会了。
3. 预览对照原样本，再观察后续原生采集。对历史材料仅在明确需要时限定重处理，不能全库重跑。
4. 每次只改变必要配置；复验同类错例，也看正常样例是否受损。保存修改前后和失败结果。
5. 若必须改变行业边界、提示词、分类或门槛文件，形成候选调整单，交业务负责人决定；当前只提出，不落地。若需新增解析能力，则标记为代码需求，退出本SOP的配置修复范围。

### 使用项目已有评测能力

- **精选评测**：`docs/selection.md`建议100—200条真实人工标注样本，分开发集和留出集；标“该选/不该选/两可”。必须包含未公开、被拦截和边界材料，不能只挑已精选内容。当前可先积累样本和评测基线，不修改线上标准。
- **执行方式**：运维准备JSONL后运行原生 `scripts/eval-selection.ts`；结果可自动导入SelectBench，或在后台导入报告。SelectBench主要用于看报告和逐例比较，不是自动标注、自动训练或自动发布新规则的编辑器。
- **看什么**：查准率、查全率、F1之外，同时看覆盖率和完整准确率；模型失败不能从总效果中隐藏。两可样本单独列出，不纳入决定样本指标。
- **范围限制**：精选评测涵盖预筛和两次评分，不覆盖完整采集、摘要事实准确性及最终去重。归组关系另用 `scripts/eval-relations.ts`；综述另用 `scripts/eval-story-digests.ts`对比，并人工核对，不能用精选F1替代整站质量。
- **变更生效**：提示词版本变化不会自动重算全部历史资料。后续若获准改行业规则，应在隔离评测环境或受控窗口评测候选，不把运行中的提示词临时改来改去；限定历史重处理范围并复验。

评测、重新分析和归组可能调用模型并计入既有预算。当前仅允许现有模型与既有服务范围，不新增付费端点；代理在本机不等于已证明模型免费。本SOP未执行模型评测或更换模型。

## 10. 每周质量记录：口径一致才可比较

以固定时间范围、信源、栏目、文章ID和修订为统计边界。下面是建议记录指标，部分需要人工汇总或只读查询，不能声称后台已经提供全部指标。

| 指标 | 分子 / 分母 | 用途和限制 |
|---|---|---|
| 有效文章比例 | 确认为真实文章的抽检条数 / 抽检入库条数 | 识别导航误采；必须写样本量 |
| 日期准确完整率 | 有可信且提取正确日期的抽检文章数 / 抽检真实文章数 | 原文无日期单独列明；不能造日期提高比率 |
| 材料可用率 | 具备足够有效正文或摘要的抽检文章数 / 抽检真实文章数 | 不要求获得全文；unconfirmed不自动算完整 |
| 公开内容正确率 | 标题、摘要、分类和关键条件均通过的抽检数 / 抽检公开条数 | 记录错误类别，不能外推全站 |
| 样本漏选率 | 人工认为该选而系统未选数 / 人工认为该选数 | 精选样本指标；不等于全网漏报率 |
| 样本误选比例 | 人工认为不该选但系统选入数 / 系统选入的有明确标注样本数 | 对照评测查准率；两可排除并另报 |
| 信源覆盖 | 已核验的范围单元 / 预定范围单元 | 31省区市按31为分母；车型、企业、出口分别统计，不混成一个百分比 |

分母为0写“不适用”，不写100%。公开率只用于定位，不作为单独绩效目标。低产出官方政策源可能仍有重要价值，不能仅按数量停用。

## 11. 留痕模板与结案条件

配套CSV仅为离线工作表，不会自动导入后台、修改数据库或执行操作。

**问题单字段**：编号、发现时间及时区、信源ID、材料ID、原文URL、栏目、修订/窗口、问题环节、原文证据、实际结果、期望结果、建议动作、授权范围、执行人、修改前配置/值、修改后配置/值、任务/回执/审计编号、复验时间、复验结果、待办原因。

**信源评估字段**：信源ID、名称、发布者、目标栏目、地区/车型/企业覆盖、等级及依据、访问条件、最近成功、样本ID、日期/正文问题、噪声、独立来源组、建议保留/修配置/暂停/待验证、依据与复验时间。

**当日结案检查**：受影响样本对照原文通过；新配置已在实际原生运行应用；前台与后台一致；审计可追溯；历史人工覆盖和其他已知问题未被误清；遗留问题仍列为未完成。入队但未完成、预览成功但未实际采集，一律不能结案。

## 12. 本站启动期优先清单

这是此前核验发现的待处理方向，不是本文编写时重新统计的实时数量，也不代表已经修复。

1. 相关内容缺可信发布日期：按源修日期读取，再看原生补全能否恢复发布资格。
2. 导航误采和正文不足：收紧列表，区分真实文章与无效页面；保留无法取得正文的边界。
3. AI相关性边界：按ED-20261024-008已批准的四层范围审校，分类标签只选一个。汽车数智应用须有具体业务或案例；企业转型层保留原行业和实施阶段；AI产业层可收模型、厂商、开源与研究动态；社区观察保留个人实测或转述身份，不因引用官方链接自动升层。不要为跨行业材料补造汽车应用。精选仍由既有评分与门槛决定；范围外的新口径交业务负责人决定。历史BLOCK不会因配置变化自动全部重算，限定重评须留授权和原文证据。
4. 地区覆盖缺口与投诉源403：保留范围矩阵和网络证据，不把曾成功当作稳定可用。
5. 真实多源热点、首期日报与最终页面：由原生流程生成后验收，不通过人工改时间、门槛或历史标记制造通过。

## 13. 企业AI应用案例按国内／国际收集与整理（ED-20261024-010）

在四层AI分类上叠加两类地域标签：`AI应用·国内`、`AI应用·国际`。只根据真实业务案例的应用地点；大陆之外包括港澳台，展示时保留具体国家或地区。厂商国籍、总部、媒体语言、发布会地点不能代替案例地点。无地点或冲突者继续按原有规则收录，并记入待核实，不强行归类。纯政策、通用教程、产品发布、计划与个人演示不作为实际企业案例。试点可以收录，但必须保留试点阶段。

每日日检分别抽查两个地域入口有新增的案例，各抽3条、不足全查；与栏目抽样重合的记录复用，不重复调用模型。检查企业、应用业务、地点原句、实施阶段、效果条件及来源身份。同文确实有两地实质案例时可双标，两组并集按文章ID去重。地域标签不提升评分、不保证精选。

每周按两套候选信源池复盘：大陆案例优先检查国内企业和云厂商的官方实践及国内媒体报道；大陆之外优先检查已有AWS、NVIDIA等官方案例和国内媒体的海外案例。信源可以跨池，但保持一个原生source ID和独立来源身份，不重复建源。同一媒体不同入口不能增加独立信源计数。新增源先验证文章链接、真实发布时间与正文，再从原生后台创建并观察定时采集。无日期的常青案例页保留候选缺口，不用采集时间冒充发布时间。当前网络可用不能称无VPN直连。

公开阅读：两个主题入口只含达到现有精选规则的案例；`/all?category=digital-ai&tag=AI应用·国内`及对应大陆之外标签查看全部合格公开案例。地点未明确的内容仍可在数字化与AI栏目阅读。题材范围、质量门槛和每日选取数量不因地域分组改变。

显示名称采用用户指定的“国内／国际”。本SOP保留“中国大陆／其外”的范围定义用于审校，不作为界面栏目名称。
